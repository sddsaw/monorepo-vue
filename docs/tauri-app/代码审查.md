## 需要修正的问题

### [P2] 全局水印不能使用 CSS 字体变量，也不会随变量变更自动重绘

- 位置：`apps/tauri-app/src/App.vue:31`；`apps/tauri-app/src/store/modules/theme/shared.ts:257`。
- 触发：启用全局水印，或者在水印启用时切换界面字体。
- 根因：`watermarkProps` 未提供具体的 `fontFamily`，NWatermark 从主题 common.fontFamily 获取 `var(--wb-interface-font, var(--wb-default-interface-font))`，再拼入 Canvas 的 `ctx.font`。Canvas 不会按 DOM 样式解析这里的自定义属性，赋值被忽略；当前 CSS 变量变更本身也不是水印绘制 watchEffect 的响应式依赖。
- 结果：水印会使用 Canvas 默认字体/字号，不能随界面切换到打包的宋体或黑体。
- 建议：维护响应式字体选择，给水印传入已解析的具体字体族；字体选择变更和相关字体加载完成后触发重新绘制，不要直接把 `var(...)` 传给 Canvas。

### [P2] 普通界面文字混入 font-mono，仍然绕过界面主字体

- 主要位置：`apps/tauri-app/src/views/workbench/components/basic/StatusBar/index.vue:54`。
- 右侧整个区域使用 `font-mono`，覆盖“未保存”提示、适配器名称、版本等普通界面文字；左侧文件区的“未载入文件”“未打开标签”等提示也在 `font-mono` 内（同文件第 45 行）。这些内容切换主字体后仍使用系统等宽字体。
- 其他同类位置：
  - `views/workbench/components/basic/MainContent/EditorBreadcrumb.vue:39`：父级等宽字体覆盖“系统首选项”等普通文案。
  - `views/workbench/components/business/test-flow/ContinuityEditor.vue:251`、`IddqEditor.vue:204`、`PmuForceEditor.vue:259`、`SuiteSummary.vue:248`：“底层原始数据结构”是界面标题，却显式使用等宽字体。
  - `views/workbench/components/business/test-flow/PmuForceEditor.vue:141` 和第 144 行：带中文的模式选项整体使用等宽字体。
  - `components/common/ComponentErrorBoundary.vue:77`：整个定位信息网格使用等宽字体，包含“组件标识”“所属文件”等标签。
  - `components/common/FallbackJsonView.vue:21`：整个区域使用等宽字体，包含“节点数据路径”说明标签。
- 建议：普通提示、标题、标签继承主字体；只在技术路径、标识符、数字、代码值等具体片段上保留等宽字体。不要把全局 `font-mono` 改成宋体/黑体，这会破坏终端和代码排版。

### [P2] 已打开的子窗口不会同步之后的字体选择

- 位置：`apps/tauri-app/src/theme/interface-font.ts:23`；`apps/tauri-app/src/views/workbench/components/basic/WindowTitleBar/components/SettingsView.vue:88`。
- 触发：先打开 Redis 调试面板等内部子窗口，再在主窗口切换字体。
- 根因：字体仅在各窗口启动时由 `restoreInterfaceFont()` 恢复一次；切换只写 localStorage 并修改当前 document，没有 storage 监听或字体变更的应用事件。Rust 创建窗口时，已存在的窗口只会被聚焦，不会重新加载。
- 结果：现有子窗口保留旧字体，新窗口与旧窗口表现不同；刷新/重新创建子窗口后才会读取新选择。
- 建议：在每个窗口启动时注册字体配置同步监听；可监听同源 storage 事件，或用已有 Tauri 应用事件机制广播字体变更，并同步更新窗口内的响应式字体状态。

- 审查目标：本地 `apps/tauri-app/src/views/workbench/components/basic/BottomPanel/`，包含面板布局、OutputTerminal 生命周期、写入/清空、滚动与主题适配。

#### 发现的问题及处理

1. **严重：切换标签导致日志丢失。** `NTabPane` 默认使用条件渲染，离开输出页时销毁终端；首次激活前组件引用为空，持续推送的日志也被丢弃。浏览器复现中旧 `.xterm` 节点断开连接，重新进入后标记日志消失。输出 pane 改为 `display-directive="show"`，终端模型常驻接收日志，仅在面板与输出标签同时可见时打开渲染器、执行 fit。
2. **严重：终端内容底部被裁切。** 未启用 animated 的 NTabs 不生成 pane wrapper，原 wrapper flex 样式无效，而 pane 的 `h-full` 占用了整个面板高度。实测 180px 面板中标题占 39px，终端内容仍占 179px。改为 pane 直接 flex 分配剩余空间，固定容器扣除上下边框；外边距从 FitAddon 测量宿主移至包装层，避免尺寸计算包含额外 padding。
3. **严重：清空输出后旧日志再次出现。** `Terminal.clear()` 同步执行、保留当前行，无法清除已经排队的异步写入。复现中写入后立即 clear，旧标记仍出现。统一通过 xterm 写入队列发送 RIS（ESC c），按先后顺序重置屏幕及历史，新日志仍正常保留。按钮与右键菜单共用 clearLog。
4. **建议：调整尺寸强制跳到最新日志。** safeFit 无条件 scrollToBottom，窗口调整后 viewportY 从 0 跳至历史末尾。现在只在用户原本位于底部时跟随底部，否则保留历史阅读位置；取消未清理的 setTimeout 重试，统一使用可取消的 RAF 和 ResizeObserver。
5. **建议：标签栏偏高与终端主题兼容。** 底部标签栏从实测 39px 收紧为默认 32px，随大字号增长，文字居中、指示线贴底；xterm 6 保留原生滚动与拖动区域，用 Naive UI 主题变量绘制 5px 细滑块，悬停加深、移出淡出；背景透明避免空白区域黑条；复制快捷键仅在 keydown 执行一次。
