# 工程数据同步与手动保存任务清单

日期：2026-11-22  
状态：待实施。以下勾选框仅表示本轮任务进度，不代表已有能力尚不存在；先核验并复用现有实现。  
需求来源：[需求理解：大文件工程数据同步与手动保存需求](./需求理解.md)。

## 1. 核验现有数据流与保存能力（P0）

- [ ] 梳理文件读取、解析、Store 提交、编辑器读取与修改、文件保存的实际调用链。
- [ ] 盘点绕过 Store action 的直接赋值、组件完整数据副本和各编辑器的 $onAction 刷新逻辑。
- [ ] 列出源文件、dataPath、编辑面板和跨模块消费者的映射关系。
- [ ] 核验已有修改版本、保存队列、来源写回及标签关闭保护，明确需复用和需补齐的部分。

完成依据：能够定位每类业务数据的唯一来源、修改入口、订阅者和保存目标。对应 R01–R10。

## 2. 明确数据选择与通知契约（P0）

- [ ] 沿用 Pinia 与 shallowRef，定义按文档或业务模块更新的通知范围。
- [ ] 将视图更新版本与保存修改版本明确区分。
- [ ] 定义共享数据订阅接口，覆盖嵌套字段、数组增删和整个对象替换。
- [ ] 明确 computed 返回同一对象及父子 props 传递时的更新方式，不能只依赖对象引用不变的计算结果。
- [ ] 处理订阅清理和工程切换后的旧订阅失效。

完成依据：两个独立消费者读取同一数据，修改任意一处后均收到正确更新。对应 R03、A02、A04、A05、A12。

## 3. 统一业务修改入口（P0）

- [ ] 复用并完善字段修改 action，统一执行输入检查、写入、修改记录及更新通知。
- [ ] 将已有增删行、列配置等业务编辑接入相同规则，不为未支持的编辑器扩展新功能。
- [ ] 批量操作合并通知，避免逐单元格重复全量校验与刷新。
- [ ] 无效输入、取消操作和相同值提交不新增修改记录。
- [ ] 保留现有“改回原值仍未保存”的语义。

完成依据：所有本期编辑入口均能正确记录修改并通知消费者。对应 R02–R04、A03、A05。

## 4. 接入表格和关联面板（P0）

- [ ] 先选择 Pin Table 验证单元格提交、Esc 取消及跨面板同步，再迁移其余受影响的现有编辑器。
- [ ] 表格读取 Store 数据，输入组件仅保留必要的未提交草稿。
- [ ] 接入共享定义生成的选项列表、统计视图等依赖，避免仅更新当前激活面板。
- [ ] 确认关闭再打开标签仍展示内存中的最新内容。

完成依据：无需手动刷新或切换标签即可看到最新数据。对应 R02、R03、R10、A02–A05、A12。

## 5. 完善手动保存链路（P0）

- [ ] 保存按钮和快捷键共用入口，先提交有效草稿；存在无效草稿时提示并阻止本次保存。
- [ ] 明确一次保存覆盖当前工程的所有已提交未保存修改。
- [ ] 按 projectDocuments 来源映射生成待保存内容；仅写入涉及的源文件。
- [ ] 复用保存队列与版本机制，避免旧写入覆盖新内容或清除保存期间的新修改。
- [ ] 核验所有编辑入口均不直接写文件，不添加定时保存或失焦落盘。
- [ ] 核验浏览器预览不支持写回时的提示与未保存标记保留。

完成依据：文件只在显式保存时变化，重载与已保存内容一致。对应 R05–R08、A06–A10、A14。

## 6. 处理失败与离开工程（P0）

- [ ] 核验原生写入的文件完整性保护，必要时采用同目录临时文件与安全替换。
- [ ] 保存失败保留内存数据；多文件部分失败不能误报整体成功，并支持重试。
- [ ] 对关闭工程、切换工程、退出桌面应用接入“保存 / 放弃 / 取消”。
- [ ] 保存失败、无效草稿或保存期间仍有新增修改时，不直接离开工程。
- [ ] 保留编辑标签关闭的既有行为，区分标签关闭与工程关闭。

完成依据：失败、取消或关闭标签均不静默丢失当前工程修改。对应 R08–R10、A10–A12。

## 7. 保存状态反馈（P1）

- [ ] 在现有界面呈现必要的保存中、成功、失败状态。
- [ ] 重复操作复用同一保存协调逻辑，避免反馈与实际文件状态矛盾。

完成依据：用户能够判断修改是否已写入文件。对应 R11。

## 8. 验收与性能验证（P0）

- [ ] 选择脱敏的约 10 MB 单文件和多文件样例，记录行数、嵌套结构与测试设备。
- [ ] 验证需求中的 A01–A14；为更新传播、保存竞态和失败重试添加必要的行为测试。
- [ ] 在真实 Tauri 桌面环境验证源文件写回与退出保护，不能只用 IPC 替身宣称磁盘保存已验证。
- [ ] 记录加载、单字段更新、关联面板更新、批量操作、保存的耗时和内存变化。
- [ ] 检查单字段编辑不复制或序列化全工程，面板反复开关无持续监听累积。
- [ ] 根据测量结果处理全工程校验、大表格全量渲染等实际瓶颈，不为预设性能问题扩大改造范围。
- [ ] 执行受影响范围的类型检查、Lint 和必要构建，记录验证结果及尚存限制。

建议顺序：先完成 1–3，以一个编辑器验证完整的“编辑 → Store → 关联视图 → 手动保存”链路，再完成 4–8。
